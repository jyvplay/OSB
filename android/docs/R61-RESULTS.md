### Additional spreadsheet increment — declared before implementation
Within the existing reviewed text-grid flow, investigate two separately opt-in controls: **skip blank input fields**, and **refuse if an existing cell would change**. Defaults must preserve R60 bytes and behavior, including blank clearing, decimal classification and transpose. Skip applies to both quoted and unquoted zero-length fields, not whitespace. Conflict protection rejects the entire proposed transaction if it would replace or clear a populated, nonidentical cell; identical cells and insertion into empty cells remain admissible. Source and destination bounds apply even when every field is skipped. All operations remain anchor/revision-bound, cancelable and one undo step; neither imports Office files nor makes CSV safe in other applications.

Before committing either control: positive/negative/exact and over-boundary host cases across all combinations of mode, transpose and controls; immutable original and no-op/overflow/revision checks; a seeded independent model and actual XLSX readback with mutated-output attacks; preserved old entry points plus pinned-old/default artifact comparison; regression on R54/R58/R59/R60; source, census, Python, syntax and whitespace gates. After push require API34 default-reset, preview/refusal, cancel/apply/undo and real provider readback plus an inspected real dialog frame. A UI test that was authored but did not run is not a pass.

## A–B. Model and outcomes

H+ is a bounded functional increment; H− is not a proof that the entire product is impossible; H∂ includes viewport/font, provider behavior, unknown OS input events and resource limits. Success for a finite candidate means all explicitly stated host and device evidence gates pass; this does not imply universal compatibility. ∀ admitted inputs is the intended contract; ∃ observed finite cases are only evidence.
