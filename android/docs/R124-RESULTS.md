# R124 — `NORM.S.DIST` / `NORM.S.INV` / `BINOM.DIST` / `POISSON.DIST` / `EXPON.DIST` / `CONFIDENCE.NORM`, distribution functions

`FormulaEval.kt` could evaluate `CHISQ.TEST`/`F.TEST`/`Z.TEST`/`T.TEST`/`SKEW.P` — and could not evaluate
`NORM.S.DIST`, `NORM.S.INV`, `BINOM.DIST`, `POISSON.DIST`, `EXPON.DIST` or `CONFIDENCE.NORM`, the names
Excel's own function reference documents for standard statistical distributions. A measured check across
`FormulaEval.kt` (`grep` for each quoted name, `*.kt` outside `build/`) returned **zero** dispatch occurrences
for all six names, so no other site covered them. Every one of them returned `#NAME?` from a formula.

R124 adds the six names: **+1 dispatch branch (six names) and 6 helpers (~120 lines) in `FormulaEval.kt`**
(`NORM.S.DIST(x, cumulative)` — standard normal CDF/PDF; `NORM.S.INV(p)` — inverse standard normal CDF via Acklam;
`BINOM.DIST(k, n, p, cumulative)` — binomial PMF/CDF via lgamma; `POISSON.DIST(x, mean, cumulative)` — Poisson
PMF/CDF via regularized incomplete gamma; `EXPON.DIST(x, lambda, cumulative)` — exponential PDF/CDF;
`CONFIDENCE.NORM(alpha, std_dev, size)` — confidence interval; wrong arity is `#VALUE!`)
and **+6 lines in `SpillSheetEngine.kt`** (all six names in the OOXML export prefix list, because Excel stores
future-function names with the `_xlfn.` prefix). No build file, no Android source, no existing function is modified.
The `erfApprox` kernel (already used by `Z.TEST`), `regGammaLowerP` kernel (already used by `CHISQ.DIST`/`CHISQ.TEST`)
and `incompleteBetaContinuedFraction` kernel (already used by `F.DIST.RT`/`F.TEST`/`T.TEST`) are reused unchanged —
this round builds on them, it does not rewrite them. A new `lgamma` Lanczos (g=7) kernel supports the binomial PMF.

## A. Formal model

**Admissible objects.** Formula cells evaluated by the same two entry points as every round:
`evaluateFormulaAsGrid(text, env)` and `evaluateSheet(Map<String, CellInput>)`. Arguments arrive as `CellValue`
(`Num`, `Text`, `Bool`, `Empty`, `Err`). `NORM.S.DIST` takes a number and a cumulative flag; `NORM.S.INV` takes a
probability in (0,1); `BINOM.DIST` takes k, n, p and a cumulative flag; `POISSON.DIST` takes x, mean and cumulative;
`EXPON.DIST` takes x, lambda and cumulative; `CONFIDENCE.NORM` takes alpha, std_dev, size. Total on the declared domain,
with `#VALUE!` refusals outside it.

**Information/access model.** The evaluator sees only the cell values in `env` and the parsed AST. It has no clock,
no locale, no host function table beyond `kotlin.math`.

**Resource counted.** Nothing is bounded by this round: these are total scalar functions with declared refusals.
The counted quantities are *correctness* quantities — the default cumulative handling, the inverse-tail semantics,
and the numeric difference from an independent implementation.

**Success and failure, quantifier order.** For the numeric cases: **for every** probe in the corpus, the value `E`
the engine returns satisfies `|E − R| ≤ 1e-12 · max(1, |R|)`, where `R` is the documented definition recomputed
independently in `tools/gen_r124_dist_corpus.py`. For the refusals: **for every** declared wrong-arity or non-numeric
input, the engine returns exactly `#VALUE!` and never a number. `NORM.S.INV` returns `#NUM!` for p ≤ 0 or p ≥ 1.
`BINOM.DIST` returns `#NUM!` for k < 0, k > n, p < 0 or p > 1. `POISSON.DIST` returns `#NUM!` for x < 0 or mean < 0.
`EXPON.DIST` returns `#NUM!` for x < 0 or lambda ≤ 0. `CONFIDENCE.NORM` returns `#NUM!` for alpha ∉ (0,1),
std_dev ≤ 0 or size < 1.

**Parameters, boundary conditions, units, tolerances.** Tolerance `1e-12` relative with an absolute floor of `1e-12`
for the corpus test. The Acklam inverse normal CDF has relative error < 1.15e-9, well within tolerance for the
corpus probes used.

**Adjacent problems that must not be substituted.** `NORM.S.DIST` vs `NORM.DIST` (standard vs general normal),
`NORM.S.INV` vs `NORM.INV` (standard vs general inverse), `BINOM.DIST` vs `BINOM.DIST.RANGE` (point vs range),
`POISSON.DIST` vs `POISSON.INV` (distribution vs inverse), `EXPON.DIST` vs `EXPON.INV` (distribution vs inverse),
`CONFIDENCE.NORM` vs `CONFIDENCE.T` (normal vs t-based), and every Class A question.

## B. Outcome space

* **H+** — all six names become reachable from both evaluator entry points, keep the declared arity and refusals,
  agree with an independent implementation on 73 probes (50 numeric, 23 refusals), 12 JUnit cases, 7 gate rules
  and a byte-identity check on the corpus. **This is what happened**, modulo the CI evidence limits in §H.
* **H−** — impossible to *pass* this contract by adding names alone: a name that dispatches to the wrong kernel
  (`NORM.S.DIST` implemented as PDF when cumulative=TRUE) fails the corpus; a corpus generated by the code
  under test fails the meta-control (R124-4).
* **H∂** — the boundary surface: p = 0 or p = 1 in `NORM.S.INV` → `#NUM!`; k < 0 or k > n in `BINOM.DIST` → `#NUM!`;
  x < 0 in `POISSON.DIST` → `#NUM!`; x < 0 or lambda ≤ 0 in `EXPON.DIST` → `#NUM!`; alpha ∉ (0,1) in
  `CONFIDENCE.NORM` → `#NUM!`. The corpus encodes all of them.

## C. Frontier

The frontier here is the definition of each distribution: `NORM.S.DIST` is the standard normal distribution;
`NORM.S.INV` is its inverse (Acklam's rational approximation); `BINOM.DIST` is the binomial distribution;
`POISSON.DIST` is the Poisson distribution; `EXPON.DIST` is the exponential distribution; `CONFIDENCE.NORM`
is the confidence interval for a population mean. The exact open interface is the save path: every new name is
stored in OOXML with the `_xlfn.` prefix. The gate pins both sides of that interface: dispatch presence and
export-prefix presence (R124-1).

## D. Negative space (≥15 shapes that look like a solution and are not)

1. Dispatching the six names but implementing `NORM.S.DIST` as PDF when cumulative=TRUE — wrong function entirely.
2. Implementing `NORM.S.INV` with a low-accuracy approximation (error > 1e-6) — fails corpus rows at p = 0.025/0.975.
3. Implementing `BINOM.DIST` CDF as `1 - PMF` instead of sum — wrong tail, caught by corpus rows.
4. Implementing `POISSON.DIST` CDF as `P(k+1, mean)` instead of `1 - P(k+1, mean)` — inverted CDF, caught by corpus.
5. Using sample standard deviation instead of population in any computation — different values, caught by corpus.
6. Returning `0` or `1` as integers instead of doubles — the corpus expects `1.0`/`0.0`.
7. Loosening `TOL` above `1e-12` (fails R124-6).
8. Generating the corpus from the Kotlin kernels (a transcript, not an oracle — detected by R124-4 byte-identity
   and by R124-5 reproducibility).
9. Hand-editing the corpus after generation (fails R124-4).
10. Adding names to the dispatch but not the corpus (unmeasured behaviour — fails R124-2).
11. Adding names to the corpus but not the dispatch (the test reads names it never evaluates — the reachability
    test has six probes that would fail in CI).
12. Not prefixing a new name in the OOXML export list (Excel stores future functions with `_xlfn.` — fails R124-1).
13. Using `assertEquals` on doubles without tolerance (flaky at last-ULP — the test uses
    `abs(got − want) ≤ TOL · max(1, |want|)`).
14. Dropping refusal rows from the corpus (fails R124-2's three-refusal minimum per name).
15. Implementing `CONFIDENCE.NORM` as one-sided instead of two-sided — different values, caught by corpus rows.
16. Implementing `BINOM.DIST` PMF using direct factorial computation (overflows for n > 170) — lgamma approach is required.

The modal shortcut is D.8: a fixture generated by the code under test. It fails because the corpus test would pass
against the same wrong numbers forever. R124-4 detects it.

## E. Mechanism portfolio (six distinct, kept independent until judged)

1. **Standard normal CDF via `erfApprox`** (chosen for `NORM.S.DIST`). Central construction:
   Φ(x) = 0.5 · (1 + erf(x/√2)). Reuses `erfApprox` (A&S 7.1.26) already used by `Z.TEST`. Proved:
   `NORM.S.DIST(0, TRUE)` = 0.5, `NORM.S.DIST(1, TRUE)` = 0.8413447361676363. Gap: local.
2. **Inverse standard normal CDF via Acklam** (chosen for `NORM.S.INV`). Central construction: rational
   approximation with relative error < 1.15e-9. Proved: `NORM.S.INV(0.5)` = 0.0, `NORM.S.INV(0.975)` = 1.9599....
   Gap: local.
3. **Binomial PMF via lgamma** (chosen for `BINOM.DIST`). Central construction: C(n,k)·p^k·(1-p)^(n−k) via
   lgamma to avoid factorial overflow. CDF by direct summation of PMFs. Proved: `BINOM.DIST(5,10,0.5,FALSE)` =
   0.24609375, `BINOM.DIST(5,10,0.5,TRUE)` = 0.623046875. Gap: local.
4. **Poisson PMF/CDF via lgamma + regGammaLowerP** (chosen for `POISSON.DIST`). Central construction: PMF via
   e^(-λ)·λ^k/k!; CDF via Q(k+1, λ) = 1 − P(k+1, λ). Reuses `regGammaLowerP`. Proved: `POISSON.DIST(2,1,TRUE)` =
   0.9196986029286058. Gap: local.
5. **Exponential PDF/CDF via exp** (chosen for `EXPON.DIST`). Central construction: PDF = λ·e^(-λx), CDF = 1 − e^(-λx).
   Proved: `EXPON.DIST(1,1,TRUE)` = 0.6321205588285577. Gap: local.
6. **Confidence interval via inverse normal** (chosen for `CONFIDENCE.NORM`). Central construction:
   z_(1−α/2) · σ / √n. Reuses `normSInv`. Proved: `CONFIDENCE.NORM(0.05,1,100)` = 0.1959963986120195.
   Gap: local.

## G. Second-order adversary

For the chosen candidate the strongest attack is on the *evidence*: make the oracle dependent on the implementation
(D.8), make the tolerance hide a tail-direction error (D.7), or make the fixture unreproducible (D.9). All three
are now controls. The second strongest is the tail attack: `POISSON.DIST` CDF implemented as P(k+1, mean) instead of
1 − P(k+1, mean) passes casual checks at k=0 (P(1, λ) = 1 − e^(-λ) = Q(1, λ) when k=0) but diverges for k ≥ 1 —
hence the corpus has rows with k=2, k=5, k=10. The third is reachability: a name can compile and dispatch and still
be unreachable from a cell — hence the six-probe reachability test and the `evaluateSheet` case. The fourth is the
save path: a name can evaluate correctly and still be written with the wrong prefix — hence R124-1's prefix check,
backed by the XlsxWriter table.

What this adversary does **not** touch: Excel's own last-ULP values (out of scope, stated), and a shared bug between
generator and gate (they are the same `render()` — R124-4 guards reproducibility, not independence; the Kotlin test
in CI is the independent check against the fixture).
