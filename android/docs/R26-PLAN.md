## A — objects, access, quantifiers and budgets

Admissible objects: existing native modules and requirement register; exact Git/source
hashes; bounded playlists (M3U/M3U8/PLS), GPX tracks, TSV worksheets, USB rules, URLs,
dock plans, palette constants; real fixture bytes; raw kotlinc/JRE outputs; official

Access: local repository/files/processes, Python/Node/git, fresh web retrieval, pinned
host compiler/JRE (kotlinc 2.2.21 + JRE 17.0.9, disposable cache). No Android SDK, JDK,
physical lab, Studio GUI run, service entitlement, firmware authority, or independent
reviewer is available in this sandbox. Remote Gradle/SDK execution happens only via
push-triggered CI and is reported from exact receipts, never inferred here.

Resource counted: **included Gradle modules with substantial operational code and a
runnable behavioral test** (testable-subset census), plus **R26 deepening**: new executed
kernels per module. Starting census 50/50 = 100% testable, 0/50 fully accepted. New
execute-here kernels may deepen rows; authored-only Android UI may not.

Quantifiers: for each claimed candidate C, declare input/runtime set D(C), threat
assumptions T(C), resource bounds B(C), and required gates G(C). Acceptance of a kernel
claim requires every named host gate to execute successfully at the attributed source.
Finite trials establish those trials only. Host passes never authorize Android, service,
anonymity, hardware or acceptance claims.

Parameter regime: palettes = 3 shipped opaque-sRGB roles; WCAG AA 4.5/3.0/3.0 with exact
recomputed ratios; floor fraction ≥ 0.80 (shipped 0.8316); dock ≤ 8 visible slots, ≥ 48dp
targets; playlists ≤ 256KiB/512 entries; GPX ≤ 512KiB/8192 points; TSV ≤ 1MiB/4096×256;
USB policy ≤ 256 rules; sandbox namespaces parse/render/convert with byte+step caps;
URLs ≤ 2048 ASCII chars. Units: dp, bytes, ratios. Tolerances: 0.01dp geometry, 1e-9
floor math, phi ± 0.05 (proportion hint only).

Adjacent problems NOT substituted: host kernels for Android; parse-gate for compilation;
contrast math for rendered-pixel/AX acceptance; phi-proximity for beauty; policy models
for OS enforcement; handoff UI for service integration; reflection probe for a bundled
engine; playlist parsing for stream extraction; Tri-state "unknown" for "safe".

## B — outcome space / evidence thresholds

- **H+**: bounded kernels (beauty budgets, amnesia/Tor/USB/keypad policy models,
  playlists, GPX, safe navigation, sandbox jobs, TSV) can be engineered and executed on
  the host with independent recomputation. Threshold: real kotlinc compile, JVM consumer
  run, Python reference agreement, fixture bytes, sha-bound census update, green
  structural suite.
- **H−**: an APK cannot become Tails; cannot prove RAM/swap/host erasure; cannot detect
  a passive logger from identical traces; cannot turn commercial service pages into free
  streams; finite pins cannot be infinite; unknown posture cannot become "safe".
- **H∂**: engine/service/privacy/visual outcomes depend on exact binaries, entitlements,
  trusted OS/hardware, resource envelopes and external validation. Keep the original goal
  and report the missing interface.

A commit/push may submit an **experimental candidate** after local structural gates,
because remote compilation requires it. That is not commitment to success. Repairs
inherit no trust.

## H/I/J — verification, repair, stopping

Prefer real external verification: kotlinc 2.2.21 output, JRE execution, independent
Python recomputation, fixture bytes, sha-bound census, 196-test structural suite. No
adequate verifier (SDK/device/human review) → authored claims stay "authored", never
"verified". Every repair re-runs affected gates and adds an attack aimed at the patch
(R26 repairs: nullable Entry guard, forensic-wording disclosure, brace-balance refusal
check, JAVA_HOME-gated syntax runner). Continue until the real budget is exhausted; if
success predicates remain unmet, return the strongest verified artifact, exact gap, and
next highest-information test — not an A-grade claim.
