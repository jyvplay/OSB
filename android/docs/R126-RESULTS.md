# R126 — `CONFIDENCE`, legacy alias for CONFIDENCE.NORM

`FormulaEval.kt` dispatched `CONFIDENCE.NORM` — and `CONFIDENCE.T` — but the SCOPE string also listed
the legacy `CONFIDENCE` name, which was **not** dispatched. A formula `=CONFIDENCE(...)` returned
`#NAME?` even though the engine's own scope declaration advertised it. A measured check across
`FormulaEval.kt` (`grep` for `"CONFIDENCE"`, `*.kt` outside `build/`) returned **zero** dispatch
occurrences for the bare `CONFIDENCE` name, so no site covered it.

R126 adds the one missing name: **`CONFIDENCE` added to the existing `CONFIDENCE.NORM` dispatch branch**
(one line change — `CONFIDENCE` shares the `CONFIDENCE.NORM` kernel, since Excel's legacy `CONFIDENCE`
is identical to `CONFIDENCE.NORM`). **One line in `SpillSheetEngine.kt`** adds `CONFIDENCE` to the
`_xlfn.` export prefix list. No build file, no Android source, no existing function is modified.
The `normSInvAcklam` kernel (already used by `CONFIDENCE.NORM`) is reused unchanged.

## A. Formal model

**Admissible objects.** Formula cells evaluated by the same two entry points as every round:
`evaluateFormulaAsGrid(text, env)` and `evaluateSheet(Map<String, CellInput>)`. Arguments arrive as
`CellValue` (`Num`, `Text`, `Bool`, `Empty`, `Err`). `CONFIDENCE` takes alpha, standard_dev, size —
identical signature to `CONFIDENCE.NORM`. Total on the declared domain, with `#VALUE!` refusals outside it.

**Information/access model.** The evaluator sees only the cell values in `env` and the parsed AST. It
has no clock, no locale, no host function table beyond `kotlin.math`.

**Resource counted.** Nothing is bounded by this round: this is a total scalar function with declared
refusals. The counted quantity is *correctness* — `CONFIDENCE` must produce bit-identical results to
`CONFIDENCE.NORM` for the same inputs.

**Success and failure, quantifier order.** For the numeric cases: **for every** probe in the corpus,
the value `E` the engine returns satisfies `|E − R| ≤ 1e-12 · max(1, |R|)`, where `R` is computed by
`tools/gen_r126_confidence_corpus.py`. **For every** probe, `CONFIDENCE(args)` must equal
`CONFIDENCE.NORM(args)` exactly (alias equivalence). For the refusals: **for every** wrong-arity or
invalid-domain input, the engine returns exactly `#VALUE!` or `#NUM!` respectively.

**Parameters, boundary conditions, units, tolerances.** Tolerance `1e-12` relative with an absolute
floor of `1e-12`. `CONFIDENCE` returns `#NUM!` for alpha ≤ 0, alpha ≥ 1, std_dev ≤ 0, or size < 1.
Returns `#VALUE!` for wrong arity.

**Adjacent problems that must not be substituted.** `CONFIDENCE` vs `CONFIDENCE.NORM` (legacy vs
modern name — must be identical), `CONFIDENCE` vs `CONFIDENCE.T` (normal vs t-based — different
functions), and every Class A question.

## B. Outcome space

* **H+** — `CONFIDENCE` becomes reachable from both evaluator entry points, produces bit-identical
  results to `CONFIDENCE.NORM`, keeps the declared arity and refusals, agrees with an independent
  implementation on 16 probes (8 numeric, 8 refusals), 10 JUnit cases, 7 gate rules and a
  byte-identity check on the corpus. **This is what happened**, modulo the CI evidence limits in §H.
* **H−** — impossible to *pass* this contract by adding the name alone: if `CONFIDENCE` dispatches
  to a different kernel than `CONFIDENCE.NORM`, the alias test fails; if the corpus is generated by
  the code under test, the meta-control (R126-4) fails.
* **H∂** — the boundary surface: alpha = 0 or 1 → `#NUM!`; std_dev = 0 → `#NUM!`; size = 0 → `#NUM!`;
  wrong arity → `#VALUE!`. The corpus encodes all of them.

## C. Frontier

The frontier here is scope/dispatch integrity: every name listed in the SCOPE string must have a
corresponding dispatch branch and `_xlfn.` export. `CONFIDENCE` was the one name that violated this
invariant. The gate pins both sides: dispatch presence and export-prefix presence (R126-1).

## D. Negative space (≥15 shapes that look like a solution and are not)

1. Listing `CONFIDENCE` in SCOPE but not dispatching it — the pre-R126 state, caught by R126-1.
2. Dispatching `CONFIDENCE` but implementing it with a different formula than `CONFIDENCE.NORM`
   — fails the alias-equivalence test.
3. Adding `CONFIDENCE` to the dispatch but not the `_xlfn.` export list — fails R126-1.
4. Adding `CONFIDENCE` to the `_xlfn.` export but not the dispatch — fails R126-6's reachability
   probes (the name would be exported but unevaluable).
5. Generating the corpus from the Kotlin kernels (a transcript, not an oracle — detected by R126-4
   byte-identity and R126-5 reproducibility).
6. Hand-editing the corpus after generation (fails R126-4).
7. Loosening `TOL` above `1e-12` (fails R126-6).
8. Dropping refusal rows from the corpus (fails R126-2's three-refusal minimum).
9. Returning `0` or `1` as integers instead of doubles (corpus expects `1.0`/`0.0`).
10. Using `assertEquals` on doubles without tolerance (flaky at last-ULP).
11. Implementing `CONFIDENCE` as `CONFIDENCE.T` (t-distribution) instead of `CONFIDENCE.NORM`
    — different values, caught by the corpus.
12. Adding `CONFIDENCE` to dispatch but not the corpus (unmeasured behaviour — fails R126-2).
13. Not updating `SCOPE` string — already correct, no change needed.
14. A shared bug between generator and gate (same `render()` — R126-4 guards reproducibility; the
    Kotlin test in CI is the independent check).

The modal shortcut is D.5: a fixture generated by the code under test. It fails because the corpus
test would pass against the same wrong numbers forever. R126-4 detects it.

## E. Mechanism portfolio (one mechanism, kept independent)

1. **Legacy name aliasing** (chosen for `CONFIDENCE`). Central construction: `CONFIDENCE` shares
   the `CONFIDENCE.NORM` kernel (`normSInvAcklam(1 − alpha/2) × std_dev / √size`), since Excel's
   legacy `CONFIDENCE` is identical to `CONFIDENCE.NORM`. Proved: `CONFIDENCE(args)` ==
   `CONFIDENCE.NORM(args)` for all corpus rows. Gap: local.

## G. Second-order adversary

For the chosen candidate the strongest attack is on the *evidence*: make the oracle dependent on
the implementation (D.5), make the tolerance hide a difference between `CONFIDENCE` and
`CONFIDENCE.NORM` (D.10), or make the fixture unreproducible (D.6). All three are now controls.
The second strongest is the kernel-substitution attack: `CONFIDENCE` implemented as `CONFIDENCE.T`
instead of `CONFIDENCE.NORM` passes a casual smoke test (both return confidence intervals) but
produces different values — hence the corpus has 8 distinct numeric rows and the alias test
compares every one.

What this adversary does **not** touch: Excel's own last-ULP values (out of scope, stated), and a
shared bug between generator and gate (they are the same `render()` — R126-4 guards reproducibility,
not independence; the Kotlin test in CI is the independent check against the fixture).
