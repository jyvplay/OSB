## A–B. Objects, boundaries and hypotheses

The objects are immutable local single-sheet drafts and their typed calculated values, formatted Writer text snapshots, frozen output copies, disposable API34 emulators, and actual files produced by their respective host or Android executions. Cells are bounded to A1:Z100, at most 256 populated inputs and 64 formulas; a copy selects at most 256 source positions. A strict Writer table has at most 64 columns and 256 header/body cells; values-only CSV has a 1 MiB output cap. Relevant observations are exact output bytes, input identity/revision, typed/formula XML, copy counts, target geometry and named JUnit outcomes—not visual guesses or invented device results.

**H+**: these bounded operations can be useful and correct for their stated finite domains, and a private cold AVD can complete the focused video experiment. **H−**: absent any actual requested run, destination readback, renderer or external application, no such behavior is inferred; a failed or skipped case remains a failure. **H∂**: arbitrary workbooks, other sheets, styles, custom formula dialects, spreadsheet consumers, font sizes, provider races, physical devices and complete product/security/AX acceptance change the problem. The new CSV check reduces common injection risks but does not claim a universal safety transformation.

The normal acceptance threshold for these feature changes remains actual kernel execution and independent readers plus adversarial/baseline tests, affected regressions, source/census/whitespace checks, **Android compilation**, exact real-device UI/provider outcomes and actual frame inspection. After the host gates passed, the user separately authorized an Office provisional commit/push solely for CI. That authorization does not waive any acceptance or GitHub protection gate.

## C. Research frontier and permissible alternatives

All product code is original; the independent pinned `openpyxl`, `python-docx`, `formualizer`, Python CSV and Pillow verifiers are host/CI tools, not Android dependencies. Microsoft's [reference guidance](https://support.microsoft.com/en-us/excel/get-started/overview-of-formulas-in-excel) distinguishes relative, absolute and mixed references, while [Microsoft's OOXML table guide](https://learn.microsoft.com/en-us/office/open-xml/word/working-with-wordprocessingml-tables) describes table/row/cell structure but does not establish rendering. The [OWASP CSV-injection guide](https://owasp.org/www-project-web-security-testing-guide/latest/4-Web_Application_Security_Testing/07-Input_Validation_Testing/21-Testing_for_CSV_Injection) warns about control/full-width prefixes, separator breakout and save/reopen; quotes alone are not a universal defense. Its suggested prefixing may change data and is not substituted for explicit refusal here.

A new differential discrepancy prompted a specific search. [A Formualizer fork PR](https://github.com/rowsncolumns/formualizer/pull/25) reports that reversed range corners formerly produced `#REF!` in its engine and says Excel normalizes them. This is a relevant external report, **not** an execution of our pinned Formualizer version or of Excel. The next discriminating test is the exact mixed-anchor `=COUNT($A3:D$2)+$C$3` output opened and recalculated in actual Excel and LibreOffice, including what each application writes back. Do not silently equate either engine with Excel.

## D. Negative space and the modal shortcut

The [plan](R64-PLAN.md) catalogs 20 rejected false solutions. Additional feature-specific counterexamples are: a copied overlap re-reading newly written cells; a protected destination partially changing; treating a stored empty string as a missing cell; dropping `$` anchors or modifying quoted formula text; trusting a correct `<f>` while its `<v>` cache is wrong; interpreting a malformed table suffix as a valid table; accidentally styling a rejected table block; accepting a stale Writer consent; silently enabling a new option on an old export; claiming quotation alone prevents CSV injection; treating a typed negative number as attacker-controlled formula text; allowing a separator to break out of a quoted cell; interpreting a reader's refusal as a match; a destination that is nonempty or aliases a known source; a duplicate XML case coalesced into one pass; and a successful screenshot transport without an actual image. **Modal shortcut:** “a compliant CSV reader sees one quoted field, therefore every spreadsheet will treat the field as inert data” is false; save/reopen and consumer type inference are different experiments.

## E–G. Mechanisms, artifacts and falsification

1. **Snapshot rectangle copy** — `OfficeSheetRangeCopy.kt` reads only the original source, recalculates the whole candidate before publication, binds the preview to exact draft identity/selection, defaults to overwrite protection, explicitly handles missing cells, and makes one undo step. Overlap/conflict/cycle/out-of-grid/stale/no-op/cap cases can falsify it. Unresolved: arbitrary Excel grammar, cross-sheet copying and styles.
2. **Independent reference relocation and caches** — actual XLSX inputs/formulas are reconstructed with `openpyxl` Translator and XML; a separate Formualizer instance evaluates formula caches. Wrong `$`, source text, typed value or cache mutations are tested. A shared library cannot prove Excel behavior; four reversed-range reference refusals are reported separately below.
3. **Strict Writer table conversion** — default-off `StructuredWriterDocx` converts rectangular, unescaped pipe blocks to actual `tbl`/`tr`/`tc` blocks, leaves malformed groups literal, and refuses bounded oversize tables. Independent `python-docx`/XML check the table contents and malformed output; separately compiled pinned old code tests unchanged defaults. Unresolved: actual Word/LibreOffice rendering and full Markdown.
4. **Values-only CSV** — `OfficeSheetCsv.kt` serializes bounded calculated data with explicit UTF-8 comma/double-quote/CRLF rules, rejects common dangerous *text* prefixes, and uses the existing frozen new-copy and readback path. Python's independent CSV implementation checks field boundaries, values and quoting; mutation attacks check breakouts and forged accepted outputs. Unresolved: the intended spreadsheet consumer's import and save/reopen behavior, and provider atomicity.
5. **User consent and persistence boundaries** — separate opt-in toggles, stale-revision checks, preview/cancel/undo, source-alias refusal and verified readback are wired into the existing UI/protocol. Static wiring checks do not run Compose or a provider. Four actual UI/provider methods and three capture routes are authored but **not yet run for this feature candidate**.
6. **Named device-case gate** — `r64_office_case_gate.py` requires all 33 actual R63 Office method names plus four R64 names, exactly once each, with no failed/skipped rows. Host adversaries cover missing, extra, duplicate, wrong SHA, malformed and failed/skip cases. It is a metadata check, not an attestation or visual inspection.
7. **Video isolation and readiness** — a private emulator, bounded package/activity/service checks, one instrumentation invocation, exact three named cases and independent actual pixel decoder form distinct gates. A connected transport alone is not a ready package service. Any later pass does not diagnose the earlier pre-case failure.
