## A. Formal problem and non-equivalences

For each executed picker case on a disposable API 34 emulator, a successful case requires a real ACTION_OPEN_DOCUMENT selection, return to the actual app, bounded processing and readback, and unchanged original bytes. The test may navigate the system picker, but may not replace its URI/result with an injected callback. ∀ passing *executed cases* these postconditions must hold; no finite subset proves ∀ OEMs, providers, device sizes, schedules or contents. Tests operate on unique disposable seeded PNG files, not user files. Foreground/selector readiness is bounded in seconds; frame geometry is measured in dp/physical pixels as recorded. Import/export fidelity, durable persistence, semantic visual quality, provider atomicity, cloud sync and security isolation are distinct predicates.

For an optional structured Writer export, any candidate must leave the existing plain export untouched; it must document exactly which textual syntax becomes which WordprocessingML blocks/runs, bound UTF-8 input/output and parser work, refuse invalid XML, and either preserve noninterpreted text or explicitly refuse ambiguous/unsupported syntax rather than silently claim fidelity. A successful DOCX package is not equivalent to arbitrary DOCX import, Word/LibreOffice rendering, rich editing, pagination, collaboration or complete Class A.

## F. Artifacts

The new original `StructuredWriterDocx.kt` is opt-in through the existing Writer DOCX disclosure. `# `–`###### ` headings, `- ` bullets and `> ` quotes apply only at the start of a nonempty line; one line always maps to one paragraph. Nonempty, non-nested `**bold**`, `*italic*` and single-backtick monospace spans become runs. If any inline delimiter on a line is unmatched, nested, escaped or ambiguous, **that line's entire inline text is literal**, although a valid leading block prefix is still converted. Other syntax has no special meaning: the supported paired inline markers are still recognized wherever they occur, including inside text resembling other syntax. Select the plain export to preserve all markers. CRLF/CR normalize to LF; tabs, surrounding spaces, blank lines and supplementary characters are retained. Input is capped at 128 KiB UTF-8, 2,048 lines and 8,192 generated runs; XML-invalid controls and unpaired surrogates are refused. This is intentionally not CommonMark/GFM, a rich editor, Office import or Word layout fidelity. The original plain export remains the default and does not interpret markers.

`DocxPackage.kt` now defines actual heading sizes/bold/outline levels, a Normal base and quote styling rather than relying only on names. Source text and the editor draft remain unchanged; the existing frozen new-copy SAF path still refuses known aliases and verifies byte readback without claiming provider atomicity. Run `python3 tools/run_r57_contracts.py`, then with separately installed `python-docx==1.2.0` run `python3 tools/check_r57_reference.py` and `PYTHONPATH=tools python3 -m unittest test_r57_reference -v`. `:testing:r57Contracts` runs in the Office Gradle CI job. Device tests require a disposable API 34 emulator and explicit opt-in, as in [BUILD.md](BUILD.md). R57 captures the actual dialog's whole display with `UiDevice.takeScreenshot`, explicitly restricted to the opted-in disposable emulator; it is not an application-window PixelCopy or a physical-device/accessibility acceptance.
