## A. Model and quantifiers
The candidate problem is **only** explicit filling of one applied formula from a selected cell across a bounded rectangle of the existing local one-sheet draft. Input is a draft that passed `OfficeSheetDraft.restore`, a selected formula source, a normalized A1:Z100 rectangle of at most 256 positions, and an explicit protection policy. Formula inputs are at most 512 UTF-16 code units with at most 32 admitted cell-reference tokens; the whole draft remains bounded to 256 populated cells, 64 formulas, 4,096 UTF-8 bytes per cell and the existing total-byte budget. Distances are integer row/column offsets; there is no numerical approximation in the coordinate mapping. Relative dimensions move by destination minus source; `$`-anchored dimensions do not. String literals, escaped quotes, numbers including exponents, functions and nonreference text must not be rewritten. Each range endpoint is shifted independently. Any translated coordinate outside A1:Z100, source-type mismatch, conflicting protected cell, formula/byte/cell limit, malformed result or new cycle refuses the entire candidate without mutation. It does **not** emit Excel `#REF!`, insert rows, import workbooks, alter styles, access external links, or claim Excel parity.

Intended contract: for every admitted `(snapshot, source, rectangle, policy)`, either all target formulas are the defined translations and one validated candidate is offered for that exact source/identity, or none are applied; after a no-op the exact original draft and undo depth remain unchanged. Success also requires explicit review, stale-snapshot refusal and independent validation; this universal intent is not a proof. Finite host corpus, real Android tests, and observed frames must be reported separately. Resource bounds count positions, reference tokens, UTF-16 units and UTF-8 bytes, not a measured latency or energy guarantee. Adjacent but different problems include arbitrary Excel formulas, named ranges, cross-sheet or structured references, full calculation semantics, Excel rendering/recalculation, large workbooks, production Office integration and arbitrary provider/device behavior.

## C. Frontier
[Microsoft's reference overview](https://support.microsoft.com/en-us/excel/get-started/overview-of-formulas-in-excel) distinguishes relative, absolute and mixed references when copying formulas; it does not establish this app's behavior. [openpyxl's Translator documentation](https://openpyxl.readthedocs.io/en/3.1/formula.html) states its formula translation is limited to A1 references and does not support defined names; it is an independent finite comparison, not an Excel evaluator. [LibreOffice's documentation](https://help.libreoffice.org/latest/ka/text/scalc/guide/relativ_absolut_ref.html) distinguishes copying references from structural row/column insertion; this candidate implements no structural move. The permissively dual MIT/Apache [Formualizer](https://github.com/convexent/formualizer) is a broader Rust engine, previously observed to diverge on some formulas, not a drop-in verified Android isolation solution. The open interface remains full grammar/recalculation, real Office verification, Android lifecycle and complete UI/provider/accessibility acceptance. Implementation is original Kotlin, not copied from these sources; external tools are host-only.

## D. Negative space and shortcut

Modal shortcut: copying the exact formula text everywhere changes relative-reference meaning; tests must assert destination-specific formulas and compare an independently translated A1 corpus.

## E–G. Mechanism portfolio and adversaries
1. **Token-aware lexical partition:** retain strings, numbers and identifiers, translate only admitted A1 references. Artifact: actual Kotlin scanner. Attack quoted `"A1"`, doubled quotes, `1E2`, mixed case and adjacent punctuation. Gap: extended Excel syntax, global.
2. **Coordinate/anchor transformation:** integer offsets applied independently to row and column with fail-closed grid boundaries. Artifact: exact mixed-anchor and range assertions. Attack four anchor combinations, negative movement, A1/Z100 and last-valid/first-invalid. Gap: Excel `#REF!`, local/interface.
3. **Immutable transaction and protection:** construct/validate a fresh candidate before review, preserving current state on every refusal. Artifact: late-conflict/cap/cycle cases and before/after snapshots. Attack conflict at last target, byte cap, formula cap and cyclic graph. Gap: external persistence, global.
4. **Identity-bound consent and undo:** reuse existing review/one-step undo contract. Artifact: no-op and stale-snapshot tests plus Android UI case. Attack same-revision distinct draft, selected-cell change, cancel and no-op. Gap: process death/OEM/UI coverage, global.
5. **Independent translator and XLSX reader:** compare actual emitted XLSX formulas and outside cells against openpyxl's independently parsed A1 translation. Artifact: seeded corpus, actual workbooks and mutant attacks. Attack wrong anchors, copied literal, omitted files and changed XML. Gap: openpyxl is not Excel and cannot recalculate, global.
6. **Baseline differential:** compile and run the earlier source alongside current code for existing clear/literal operations. Artifact: pinned outputs. Attack default change, enum expansion and behavior regression. Gap: finite baseline corpus, local.
7. **Android integration and frame:** actual one-shot typed formula input, review, cancel/apply/undo/export and UI capture. Attack stale control state, clipped disclosure and provider readback. Gap: unavailable until real emulator CI and then only one environment, global.
