## A. Formal problem
A draft is an immutable revision and map of up to 256 typed cells in A1–Z100. An explicit user action may supply bounded tab-delimited text and a selected anchor. ∀ accepted inputs in the stated grammar, preparation returns one immutable preview computed against that exact draft; confirming the still-current preview installs the entire validated new draft as one undoable operation. ∀ rejected, cancelled, stale or out-of-bounds inputs, the prior draft and its recovery bytes remain unchanged by the paste operation. This is a finite local contract, not ∀ possible devices/providers/schedules. Empty fields clear target cells; nonempty fields are **text**, even if they begin `=`, `+`, `-` or `@`. No hidden clipboard read, network, external file import, formula evaluation of pasted strings or mutation of the source is allowed. Limits and quoting are defined with the implementation, not assumed to match arbitrary Excel clipboard formats.

A valid XLSX package is not independent recalculation, arbitrary Office import, rich formatting preservation, safe CSV for all applications, cloud durability or proof of Class A. Success of a UI semantics assertion also is not proof all text is visible: the [Compose test reference](https://developer.android.com/reference/kotlin/androidx/compose/ui/test/package-summary) says `assertIsDisplayed` requires only a portion of bounds visible.

## B. Outcome space
- H+: an explicitly bounded, user-confirmed text-grid operation is achievable with real code and reproducible observable cases.
- H−: no impossibility result for the complete original product is asserted. Finite tests cannot establish universal Class A or universal provider identity/atomicity.

## C. Research and boundaries
[Microsoft's text format description](https://support.microsoft.com/en-us/excel/excel-formatting-and-features-that-are-not-transferred-to-other-file-formats) distinguishes tab-delimited values from formatting and notes quoted data. It does not certify this implementation's interoperability. [OWASP's CSV-injection guidance](https://owasp.org/www-community/attacks/CSV_Injection) warns quoting a CSV does not prevent spreadsheet formula interpretation and that no universal CSV mitigation fits every consumer. This design stores explicitly typed XLSX inline strings, not CSV; it does not claim all downstream importers remain safe. [CellarKt](https://klibs.io/project/VizGhar/CellarKt) describes an MIT Kotlin write-only XLSX generator and separate text/formula types; it was reviewed as an alternative but is not adopted or independently validated. [Compose keyboard API](https://developer.android.com/reference/kotlin/androidx/compose/ui/platform/SoftwareKeyboardController) describes `hide()` as best effort; [window insets](https://developer.android.com/develop/ui/compose/system/insets) describe IME-occupied space. These are not evidence of this app's actual failure mechanism. The `c1df68e` [R24 appearance run 41209730640](https://github.com/jyvplay/OSB/actions/runs/41209730640) separately had 3 passes/1 failure: a 200% font test reported `SnapshotStateObserver` access on two threads. Another project's [instrumentation report](https://github.com/vcheesbrough/v-note/pull/72) attributes similar errors to its test dispatcher and background state writes; OSB uses a different Compose version, and its actual cause is not established. Do not re-label this as a known flake or apply an unverified library upgrade.

## F. Artifacts and G. Adversarial checks
`OfficeSheetTextGrid.prepare` is original code. It accepts at most 64 KiB UTF-8, at most 256 fields, no more than 26 columns/100 rows and the draft's 4,096-byte cell limit. Tabs and CR/LF/CRLF separate unquoted fields/rows; an entire quoted field may contain tabs/newlines and doubles `"` to represent one quote. One trailing record separator is ignored. Bare/malformed quotes, ragged rows, controls invalid in XML, unpaired surrogates and off-sheet/over-budget plans are refused. Empty fields clear targets and all nonempty fields become typed text. A plan reports inserted/replaced/cleared/unchanged counts, is bound to the exact draft instance and anchor, and increments the revision once only if something changed. No raw input is automatically read from the clipboard or persisted separately.

On the host, `python3 tools/run_r58_contracts.py` passed **6,428 assertions**, including 500 deterministic quoted-grid cases, exact/over byte, row, column, cell and field boundaries, source immutability, stale/no-op plans and a real generated XLSX. `python3 tools/check_r58_reference.py` independently passed **31** TSV/ZIP/XML/openpyxl predicates, including the formula-looking B1 typed as a string, not `<f>`; `PYTHONPATH=tools python3 -m unittest test_r58_reference -v` passed **9** comparator/missing-artifact cases. Openpyxl reads cached values and does not execute Excel. The Android UI, revision/undo orchestration, private AtomicFile checkpoint, provider readback and new dialog are authored and not yet compiled or executed on Android. Attack malformed final fields, escaped quotes, embedded delimiters, UTF-8/XML, stale previews, undo/redo, cancellation and source preservation; do not promote authored-only checks into observed passes.
