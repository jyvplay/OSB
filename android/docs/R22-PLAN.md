# R22 preimplementation contract — 2026-10-16

Early independent mechanism branches (same author, not independent agents):
1. Strict ZIP envelope: local/central agreement, contiguous records, bounded actual inflate/CRC, no ZIP64/encryption/descriptors/comments/unknown parts. Actual byte experiments, not metadata-only size checks.
2. Bounded namespace-aware UTF8 XML: reject declarations/comments/CDATA beginning `<!`, processing instructions, excess depth/nodes/attributes/text; entity resolver refuses. Platform spike before Office feature code. Not general XML compatibility.
3. Values-only XLSX: single visible worksheet, explicit package relationships, sparse coordinates preserved, literal/shared strings and raw numeric/boolean values. Reject formulas/errors/dates/merges/hidden structures and unknown parts. Formatting/layout/metadata omitted in a NEW projection, never save back.
4. Reuse actual isolated-UID readonly-unlinked-FD boundary, add 2MiB owned XLSX request with bounded reply correlation. Prior R21 b96f060/38849172796 passed109 native cases; new operation still needs fresh tests before UI acceptance.
5. Explicit system-picker read-only import and frozen snapshot, no persistent grant, no write to source, loss of pending import/export after recreation must refuse. Actual provider/UI tests, not a mock provider.
6. Browser document suspension for renderer lifecycle: revoke pending/granted capabilities without asserting any real browser engine integration. No generic WebView promotion.
7. Exact-candidate verification policy; retain failures and reject global anonymity/full-product shortcuts even with green scoped runs.

Admissible input: stable caller-owned XLSX bytes<=2MiB; <=16 allowlisted ASCII file parts, per expanded part<=1MiB, aggregate<=2MiB; matching headers/CRC/exact raw-deflate consumption. XML depth<=32, nodes<=20000, attributes/mappings<=16 per element, UTF8 only; no DTD/CDATA/comments/PI. Table<=256 rows×32columns, <=4096 UTF16 units/cell and existing131072-byte result frame. Unsupported format features refuse. XLSX import is a lossy new text projection, not a backup or Office parity. Raw numeric/boolean encodings become literal text; style/date interpretation is not performed.

For every admitted package, local and central member identities agree, no unaccounted member bytes remain, and parser output preserves admitted cell coordinates/values under declared text semantics. For every explicit import/save, original URI is never opened for output; saved output must match frozen generated bytes on readback. For every suspension, prior prompts/grants cannot be reused; caller must deliver real lifecycle events. No universal claim over hostile kernels, providers, IMEs, engines, all XML/ZIP dialects or all Office files.

H+: bounded read-only projection and capability lifecycle are achievable under trusted parent/platform/caller assumptions. H-: app/emulator cannot hide all host/external activity or retroactively anonymize existing logs. H-boundary: format/size/resource/ownership/event and licensing interfaces. Threshold: compile + actual host references, recorded Android platform spike before feature implementation, then fresh named native operation/UI and whole relevant CI. Committing code only requests verification; it is never acceptance.
