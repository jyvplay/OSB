## 1. Live Web-Search Verification (`2026-10-26`)

1. **Tails 7.x Amnesic OS Cadence, CVE-2026-113470 & Bounded Shutdown (`TailsCadence`, `CtSctPolicy`)**:
   - Primary sources: Tails News (`https://tails.net/news/index.en.html`), Tor Project Blog (`https://blog.torproject.org/new-release-tails-7_15_1/`), Tails 7.14/7.15 release notes (`https://tails.net/news/version_7.14/`, `https://tails.net/news/version_7.15/`).
   - Verified facts as of `2026-10-26`:
     - Tails `7.15.1` (emergency release on `2026-10-23`, built on Debian 13 Trixie + Linux 6.12 LTS + Wayland) is the active release ahead of the scheduled `~2026-10-27/28` Tails `7.16` window.
     - Tails 7.x switched in early 2026 to a **biweekly (`~14-day`) release cadence** synchronized with Firefox / Tor Browser rapid point releases; unexpected out-of-band gaps (`< 7 days` emergency security spin vs `> 28 days` stale update channel / freeze attack) carry operational security significance.
     - `CVE-2026-113470` (Oct 2026): eMudhra issued 8 TLS subordinate CA certificates with `3–8` bits of key entropy, allowing practical RSA key recovery and TLS MITM against non-CT-enforcing clients; Tails `7.15.1` shipped Tor Browser `15.0.26` and `ca-certificates 20250419+deb13u1` distrusting eMudhra, while noting that **Certificate Transparency (RFC 6962) SCT enforcement** mitigated unlogged forged leaf certificates on CT-enforcing clients.
     - Tails `7.14` introduced a **60-second hard-deadline graceful shutdown timer** before forced poweroff/memory-wipe fallback so hung user-space processes cannot stall emergency amnesia.

2. **Hardware Keyloggers, BadUSB/O.MG HID Implants & Early-Boot / Locked-Port DMA (`HidReportAudit`, `DmaGuardAudit`, `OverlayTouchGuard`)**:
   - Primary sources: USB-IF *Device Class Definition for Human Interface Devices (HID) Version 1.11* (§6.2.2 Report Descriptor items, Appendix B.1 Boot Keyboard 8-byte input report), Linux `hid-omg-detect` behavioral HID research (`https://www.phoronix.com/news/hid-omg-detect-Malicious-HID`), Rapid River hardware defense taxonomy (`https://rapidriverskunk.works/OffSecHWDefense.html`), UEFI early-boot DMA / DMAR opt-in gap (`https://thehackernews.com/2025/12/new-uefi-flaw-enables-early-boot-dma.html`), IOMMU strict DMA protection (`https://header7f.com/blog/dma-attack-crypto-wallet-iommu/`).
   - Verified engineering facts:
     - **Active inline/cable implants** (O.MG Cable, USB Rubber Ducky, Bash Bunny, BLE keystroke injectors) expose composite USB HID descriptors (e.g., presenting Mouse `0x01/0x02` or Mass Storage alongside an unannounced Keyboard `0x01/0x06` collection or Vendor-Defined usage page `0xFF00..0xFFFF` C2 channel) and emit superhuman keystroke bursts (`< 8 ms` IKI, `0 ms` press-to-release dwell, GUI-modifier command chords `GUI+R` / `CTRL+ALT+T`).
     - **Passive inline USB hardware taps** sit electrically on `D+/D-` without enumerating a new USB endpoint (unless introducing an extra hub tier); software cannot prove their absence on an untrusted wired keyboard, so high-risk passphrase entry must either switch to an **obscured-touch/overlay-guarded randomized on-screen keypad** or surface an explicit unverified-wired-bus warning.
     - **PCIe / Thunderbolt / USB4 DMA**: OS-level `iommu.passthrough=0` (`iommu.strict=1`, no-ATS on untrusted external ports) AND firmware pre-boot `DMAR`/`IVRS` DMA-protection opt-in are both required; screen-locked posture must block new external PCIe/USB data tunneling (`deny_new_usb` / USB-C power-only while locked).
     - **Android local screen/input capture**: `MotionEvent.FLAG_WINDOW_IS_OBSCURED` (`0x1`) / `FLAG_WINDOW_IS_PARTIALLY_OBSCURED` (`0x2`), `WindowManager.LayoutParams.FLAG_SECURE`, non-physical virtual presentation displays, and enabled `AccessibilityService` capabilities (`canRetrieveWindowContent`, `canPerformGestures` — abused by RatHat/banking trojans) must be gated fail-closed on sensitive surfaces.
