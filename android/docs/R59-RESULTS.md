## A. Admissible objects and quantifiers
A local immutable `OfficeSheetDraft` contains at most 256 typed cells in A1–Z100. A user supplies a bounded 64 KiB rectangular tab-delimited grid to one selected anchor and explicitly chooses text-only (the default) or decimal interpretation. For every accepted grid in the documented grammar, preparation either produces one revision-bound immutable preview without changing the original, or refuses the whole operation. For every explicit confirmation of a still-current preview, apply all validated changes once as one undo step; cancelled, stale and malformed previews change no cells. This quantifies the local model and finite checked scenarios, not arbitrary providers, memory failures, users, devices or external applications. Resource units are UTF-8 bytes, fields, cells, revisions and 48 dp UI bounds.

In opt-in mode, unquoted ordinary decimal tokens with no leading integer zeros, sign-plus, exponent, trailing fractional zeros or negative zero, at most 15 significant digits and a finite binary64 value whose canonical decimal round-trip equals the entered decimal become numeric. All other nonempty fields—including quoted numbers, long identifiers and formula-looking strings—remain text. Empty fields clear targets. Numeric values are binary floating-point approximations; e.g. 0.1 is not exactly representable in binary. This rule is not lossless arbitrary decimal arithmetic, locale detection, general CSV/XLSX import, automatic formula import, or an Excel compatibility guarantee. No hidden clipboard read, network or original-file overwrite is introduced.

## C. Frontier and interfaces
[Microsoft](https://learn.microsoft.com/en-us/troubleshoot/microsoft-365-apps/excel/floating-point-arithmetic-inaccurate-result) describes Excel's finite floating-point precision and approximately 15 decimal digits; this does not prove that Excel and this implementation behave identically. [Oracle's BigDecimal documentation](https://docs.oracle.com/javase/8/docs/api/java/math/BigDecimal.html) distinguishes the exact binary value from `valueOf(double)`, which uses the canonical decimal string; equality to that string is only a decimal round-trip test, not proof of exact binary representation. [Android's clipboard-security guidance](https://developer.android.com/privacy-and-security/risks/secure-clipboard-handling) describes sensitive preview flags; this feature does not read the clipboard automatically or promise protection against other applications. The unresolved interface is the real Android user action, checkpoint and provider execution plus downstream Excel/LibreOffice interpretation.

## D. Misleading outcomes and modal shortcut
1. Auto-convert without user consent. 2. Convert quoted identifiers. 3. Strip leading zeros. 4. Lose trailing fractional zeros. 5. Change negative zero. 6. Treat `=1+1` as a formula. 7. Admit plus-prefixed formula-like text. 8. Parse locale commas as decimals. 9. Convert exponent notation without disclosure. 10. Round 16-digit identifiers. 11. Accept Infinity. 12. Underflow a nonzero to zero. 13. Call canonical decimal round-trip exact binary arithmetic. 14. Count inserted cells but omit replacements/clears. 15. Apply a partially invalid rectangle. 16. Apply a stale preview. 17. Lose undo or change multiple revisions. 18. Treat an openpyxl cached value as recalculation. 19. Call a frame or emulator pass universal accessibility. 20. Promote missing CI images to visual success.

The modal shortcut is `field.toDoubleOrNull() != null`: it incorrectly converts `0012`, `1e3`, `+7`, signed zero and over-precision values, and can accept non-finite values. The typed classifier and an adversarial test corpus must detect these differences rather than silently broadening the contract.
