## A. Formal model
Inputs are immutable local UTF-8 Writer drafts with at most 128 KiB and 2,048 normalized lines; a user explicitly chooses plain or formatted DOCX copy and may separately choose the new restricted numbered-line interpretation. Output is a new bounded DOCX, not an overwrite of the source. For every accepted draft and selected mode, generate one immutable copy or refuse the whole conversion; for every default-mode input preserve the R57 output behavior. In the opt-in mode, only documented `1. ` prefixes with following content become level-zero numbered paragraphs. Unmatched/ambiguous inline markers remain literal. Numbering is a DOCX numbering instance; the output does not assert independent restart of separated groups, exact rendering, arbitrary Markdown, nesting or rich editing. Formulas, bytes, lifecycle and provider conditions in the spreadsheet remain governed by R59/R22 contracts.

The access model includes source, bounded inputs, independently produced ZIP/XML/python-docx inspection and an API34 emulator; it excludes hidden Office engines, production provider identities, physical devices and omniscient concurrency observations. Resources include UTF-8 bytes, lines, text runs, XLSX cells, XML nodes and the existing five-second worker lifetime. ∀ admitted local inputs the implementation must satisfy its grammar and atomicity; ∃ finite executable cases and independent readers provide evidence but do not prove ∀ external devices, providers or Office programs. User cancellation must not apply a copy, a stale confirmation must not authorize a different draft, and defaults must not silently become the opt-in mode.

## C. Research frontier
[Microsoft's NumberingId reference](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.numberingid?view=openxml-3.0.1) states that `w:numId` selects a numbering-definition instance; [NumberingProperties](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.numberingproperties?view=openxml-3.0.1) associates a paragraph with `numId` and `ilvl`. A Microsoft Q&A discussion offers conflicting advice about restart behavior across instances; it is not an interoperability proof. This implementation therefore discloses shared-instance behavior rather than promising arbitrary restart semantics, and does not adopt outside code. [Android's Binder DeathRecipient reference](https://developer.android.com/reference/android/os/IBinder.DeathRecipient) says the callback observes process death, not why the process died. At R59 the death near the 5-second watchdog is consistent with its limit but could have another cause. [Android's AGP 9.1.1 notes](https://developer.android.com/build/releases/agp-9-1-0-release-notes) specify Gradle 9.3.1/JDK17 and API37.0 support; [Studio compatibility](https://developer.android.com/build/releases/about-agp) lists Rabbit 1 support for AGP7.1–9.4. This is documentation compatibility, not an observed Studio GUI run. General DOCX fidelity and physical/provider/security acceptance remain open.

The tempting shortcut is to convert every `^\\d+\\. ` line by dropping its number and assigning a common list instance. It changes old literal text, silently changes explicitly written starting values and obscures sequence/restart behavior. The default-preservation and `2. `, `01. `, nested/empty-marker adversarial cases must fail such an implementation.
