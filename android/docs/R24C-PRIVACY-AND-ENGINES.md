## What actually helps against local hardware-origin attacks

1. **New or changed HID environment:** active private input is discarded and latched when Android reports a device/configuration change. Review and physically disconnect unrecognized keyboards, adapters and cables. Descriptor/vendor names are not authenticated identities.
2. **Keyboard-only recording:** use the existing touch-only pad for its narrow digits-only use. A trusted password manager/passkey or separate trusted-device approval can avoid typing reusable secrets, but neither is integrated as a security service here. The ordinary scratchpad still trusts its IME/keyboard.
3. **Overlay and focus substitution:** existing secure/overlay/touch-admission controls remain; the patch adds no bypass. A full activity sandwich or privileged observer is not ruled out merely by checking one MotionEvent flag.
4. **Unexpected display/mirroring changes:** observed additional-display changes discard; secure-window rules remain. A malicious host can record an emulator before the guest sees anything unusual.
5. **DMA/Thunderbolt/USB policy:** use a maintained OS, firmware updates, secure boot and the platform's DMA/authorization policies, with an administrator-tested recovery path. This app does not possess those privileges. The readonly probe deliberately does not disable USB or claim that a sysfs count proves isolation.
6. **Physical implants/preexisting loggers:** inspect and control custody of the hardware; use a separate trusted machine for high-risk secrets. No software-only "scan" in this app can certify their absence.

No measured prevalence dataset was available, so these are concrete attack mechanisms, not a fabricated ranking of the most common attacks. They close narrower **application-level exposure paths**, not all hardware weak points.

### Conditional impossibility argument: invisible passive logger

Let an ordinary app receive only the OS/API transcript O, and let W0 be trusted hardware without a logger. Construct W1 with an inline passive logger that copies keyboard signals without changing any signal delivered to the OS, descriptor, timing observable to this app, or app-visible state. Under this stipulated passive attacker, `distribution(O | W0) = distribution(O | W1)`.

Any app-only decision procedure D, even randomized, must therefore have the same output distribution in both worlds. It cannot satisfy both `Pr[D(O)=clean | W0] >= 1−ε` and `Pr[D(O)=clean | W1] <= ε` for `ε < 1/2`. Additional trusted physical measurements or a change of input channel changes the access model; an ordinary status panel does not. This is a causal indistinguishability argument under explicit hypotheses, not a theorem-prover or universal hardware-attestation result.

A compromised host/firmware has an even stronger position: it can preserve the entire guest transcript while copying it. No Tor setting, random keypad or APK size comparison overturns that trust boundary. Tails itself documents hardware/firmware limits. [1](https://tails.net/doc/about/warnings/index.en.html)

## Mechanism-distinct ways forward for Major browser / Office / sandbox / productivity

The alternatives below are not six names for the same missing wrapper. Each has a concrete existing or new artifact, its own falsifier, and a stated gap. None is claimed as a completed full engine.

| Route | Central construction / artifact | Established bounded portion | Exact unresolved interface / adversary / gap type |
|---|---|---|---|
| 1. Platform renderer compartment | Existing remote-surface browser probes and isolated native PDF worker (`BrowserSurfaceDeviceTest`, `R24PdfDeviceTest`) | Real platform rendering paths and prior candidate-specific surface/FD tests exist; current regressions must rerun | General browser broker, permissions, file access, profile isolation, IME and crash/recreation; hostile navigation while a permission request is pending. Local integration gaps, full-browser scope still large. |
| 2. Pinned GeckoView runtime | `tools/engine_intake.py` + actual runtime/session/delegate design | Intake can inventory ELF/ABI/notices without executing an unknown binary. A documentation page or wrapper is not the missing engine. Mostly the original full-engine interface. |
| 3. Native LibreOfficeKit worker | Existing isolated descriptor/raw-frame transport + upstream JNI/C API boundary | Native load/conversion/tile APIs are real upstream interfaces; existing PDF/worksheet raw-result bounds can carry a subset | Build real Android ABI payload, immutable asset/fonts tree, disable external links/macros by supported engine policy, exact document fidelity/edit/save corpus and callback teardown. Malicious document/engine and stale tile attacks; original Office integration gap. |
| 4. Offline native bounded formats | Existing literal XLSX/CSV/PDF/task implementations plus new saved tabletop/map/native-media workflows | Useful code can be compiled/run with finite caps, no network account or full-engine artifact required | Not general formulas/charts/layout fidelity/macro execution, DOCX/LOK editing or service streaming. | 5. | 6. Explicit network/service boundary | New `ServiceLink`, confirmation UI and official-player handoff | No hidden provider contact by link parsing; malformed origins/credentials/shorteners/ambiguous video IDs fail; no bundled service SDK | Provider playback/DRM/account/legal/region restrictions stay outside the app. A successful Intent is not successful streaming. ### Quantitative boundaries

- Table floor corners `(0.055,0.12), (0.945,0.12), (1,1), (0,1)` give normalized trapezoid area `(1−0.12) × (1−0.055) = 0.8316`. This is **83.16% of the scene**, excluding app chrome and overlapping windows. It is not a claim that 83% of a phone screenshot is unobstructed floor.
- Up to 512 pins, 128 piles and 16 saved scenes. The codec enforces a 2MiB byte cap before parsing. With admitted name/target lengths its maximal field budget is about 1.30MB; there is no physically infinite storage claim. Pan coordinates are finite ±1,000,000 world units; zoom is 0.5–3.
- A 3840×2160 RGBA frame is 33,177,600 raw bytes; at 60 frames/s it is 1,990,656,000 bytes/s before overhead. Tiled/shared-surface transport and damage tracking are not optional for a large interactive engine; a single Binder byte-array reply is not a full desktop compositor design.
- New offline land asset is exactly 98,159 bytes. That is an asset measurement, not a claim about APK RSS, installed footprint, Android+emulator+host resources or being lighter than Tails.
- Great-circle map distance uses a sphere of mean radius 6,371,008.8m. It is not an ellipsoidal survey, road distance or directions. Mercator drawing clamps latitude at ±85.0511287798066°; saved coordinates keep their admitted ±90° values.
