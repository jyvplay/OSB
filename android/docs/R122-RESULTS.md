# R122 — `PHI` / `DELTA` / `GESTEP`, standard normal PDF and engineering comparisons

`FormulaEval.kt` could evaluate `BESSELJ`/`BESSELI`/`BESSELK`/`BESSELY`/`ERF.PRECISE`/`ERFC.PRECISE`
— and could not evaluate `PHI`, `DELTA` or `GESTEP`, the names Excel's own function reference
documents for the standard normal probability density and engineering value comparisons. A
measured check across `FormulaEval.kt` (`grep` for each quoted name, `*.kt` outside `build/`)
returned **zero** dispatch occurrences for all three names, so no other site covered them.
Every one of them returned `#NAME?` from a formula.

R122 adds the three names: **+1 dispatch branch (three names) and 3 helpers (`phi`, `delta`,
`gestep`) in `FormulaEval.kt`** (`PHI(x) = exp(-x^2/2)/sqrt(2*pi)`; `DELTA(a, b) = 1` if
`a == b` else `0`; `GESTEP(x, [step]) = 1` if `x >= step` else `0`, step defaulting to `0`;
wrong arity is `#VALUE!`) and **+3 lines in `SpillSheetEngine.kt`** (all three names in the
OOXML export prefix list, because Excel stores future-function names with the `_xlfn.`
prefix). No build file, no Android source, no existing function is modified.

## A. Formal model

**Admissible objects.** Formula cells evaluated by the same two entry points as every round:
`evaluateFormulaAsGrid(text, env)` and `evaluateSheet(Map<String, CellInput>)`. Arguments
arrive as `CellValue` (`Num`, `Text`, `Bool`, `Empty`, `Err`). `PHI` takes exactly one
numeric argument; `DELTA` takes exactly two; `GESTEP` takes one or two (second defaults to
`0`). Total on the declared domain, with `#VALUE!` refusals outside it.

**Information/access model.** The evaluator sees only the cell values in `env` and the parsed
AST. It has no clock, no locale, no host function table beyond `kotlin.math`.

**Resource counted.** Nothing is bounded by this round: these are total scalar functions
with declared refusals. The counted quantities are *correctness* quantities — the default
step argument for `GESTEP`, exact-equality semantics for `DELTA`, and the numeric difference
from an independent implementation.

**Success and failure, quantifier order.** For the numeric cases: **for every** probe in the
corpus, the value `E` the engine returns satisfies `|E − R| ≤ 1e-12 · max(1, |R|)`, where `R`
is the documented definition recomputed independently in `tools/gen_r122_phi_corpus.py`.
For the refusals: **for every** declared wrong-arity or non-numeric input, the engine returns
exactly `#VALUE!` and never a number. `DELTA` uses IEEE 754 equality (`0 == -0` is `1`);
`GESTEP` uses `>=` comparison.

**Parameters, boundary conditions, units, tolerances.** `PHI` is defined for all real `x`;
`DELTA` and `GESTEP` for all real arguments. Tolerance `1e-12` relative with an absolute
floor of `1e-12` for the corpus test. `GESTEP(x)` with one argument is identical to
`GESTEP(x, 0)`.

**Adjacent problems that must not be substituted.** Excel's display (number formats),
`PHI` vs `NORM.S.DIST` (PDF vs CDF — different functions), `DELTA` vs `EXACT` (numeric
equality vs text-exact comparison), `GESTEP` vs `IF` (threshold vs conditional), and every
Class A question.

## B. Outcome space

* **H+** — all three names become reachable from both evaluator entry points, keep the
  declared arity and refusals, agree with an independent implementation on 109 probes,
  10+ JUnit cases, 7 gate rules and a byte-identity check on the corpus. **This is what
  happened**, modulo the CI evidence limits in §H.
* **H−** — impossible to *pass* this contract by adding names alone: a name that dispatches
  to the wrong kernel (`GESTEP` implemented as `>` instead of `>=`) fails the corpus; a
  corpus generated by the code under test fails the meta-control (R122-5).
* **H∂** — the boundary surface: `DELTA(0, -0)` → `1` (IEEE 754 equality); `GESTEP(0)` →
  `1` (step defaults to 0, `0 >= 0`); `GESTEP(x < step)` → `0`. The corpus encodes all of
  them.

## C. Frontier

The frontier here is the definition of each function: `PHI` is the standard normal
probability density function, `DELTA` is the Kronecker delta (numeric equality test),
`GESTEP` is the step threshold test. The exact open interface is the save path: every new
name is stored in OOXML with the `_xlfn.` prefix (XlsxWriter 3.3.3 `FUTURE_FUNCTIONS`
table). The gate pins both sides of that interface: dispatch presence and export-prefix
presence (R122-1).

## D. Negative space (≥15 shapes that look like a solution and are not)

1. Dispatching `PHI`/`DELTA`/`GESTEP` but implementing `PHI` as the CDF (`NORM.S.DIST`)
   instead of the PDF — differs by definition, caught by the corpus at every row.
2. Implementing `GESTEP` as strict `>` instead of `>=` — `GESTEP(0)` would return `0`
   instead of `1`, caught by the corpus.
3. Forgetting the default step argument for `GESTEP` — `GESTEP(1)` must behave like
   `GESTEP(1, 0)`.
4. Implementing `DELTA` with text-exact comparison (`EXACT`) instead of numeric equality —
   `DELTA("1", 1)` semantics differ.
5. Returning `0` or `1` as integers instead of doubles — the corpus expects `1.0`/`0.0`.
6. Loosening `TOL` above `1e-12` (fails R122-6).
7. Generating the corpus from the Kotlin kernels (a transcript, not an oracle — detected by
   R122-5 byte-identity and by the gate recomputing each row from `gen_r122_phi_corpus.py`).
8. Hand-editing the corpus after generation (fails R122-5).
9. Adding names to the dispatch but not the corpus (unmeasured behaviour — fails R122-2).
10. Adding names to the corpus but not the dispatch (the test reads names it never evaluates
    — the reachability test has three probes that would fail in CI).
11. Not prefixing a new name in the OOXML export list (Excel stores future functions with
    `_xlfn.` — fails R122-1).
12. Implementing `DELTA` with floating-point epsilon comparison instead of exact `==` —
    `DELTA(0.1 + 0.2, 0.3)` semantics differ from Excel.
13. Using `assertEquals` on doubles without tolerance (flaky at last-ULP — the test uses
    `abs(got − want) ≤ TOL · max(1, |want|)`).
14. Dropping the refusal rows from the corpus (fails R122-2's five-refusal minimum per name).
15. Implementing `GESTEP(x)` with one argument as `x > 0` instead of `x >= 0` — `GESTEP(0)`
    would return `0` instead of `1`.

The modal shortcut is D.7: a fixture generated by the code under test. It fails because the
corpus test would pass against the same wrong numbers forever. R122-5 detects it.

## E. Mechanism portfolio (four distinct, kept independent until judged)

1. **Standard normal PDF via `exp(-x^2/2)/sqrt(2*pi)`** (chosen for `PHI`). Central
   construction: direct evaluation of the Gaussian density. Proved: every numeric corpus row
   agrees with the generator to 1e-12, and `PHI` is positive and finite for all `x`.
   Cheapest falsification: `PHI(0)` must be 0.3989422804014327. Gap: local (no Kotlin
   compiler; CI is the sole compiler — disclosed in §H).
2. **Exact IEEE 754 equality** (chosen for `DELTA`). Central construction: `a == b` returns
   `1.0` if true, `0.0` otherwise. Proved: `DELTA(0, -0)` = 1, `DELTA(1, 2)` = 0.
   Cheapest falsification: `DELTA(1, 1)` must be `1.0`. Gap: local.
3. **Threshold `>=` with default step = 0** (chosen for `GESTEP`). Central construction:
   `x >= step` returns `1.0` if true, `0.0` otherwise; one-argument form uses `step = 0`.
   Proved: `GESTEP(0)` = 1, `GESTEP(-1)` = 0, `GESTEP(1, 1)` = 1, `GESTEP(0.999, 1)` = 0.
   Cheapest falsification: `GESTEP(0)` must be `1.0`. Gap: local.
4. **`PHI` as CDF instead of PDF** (rejected). `NORM.S.DIST` already covers the CDF; `PHI`
   is the density — implementing it as the CDF would be a different function.

## G. Second-order adversary

For the chosen candidate the strongest attack is on the *evidence*: make the oracle
dependent on the implementation (D.7), make the tolerance hide a sign error (D.6), or make
the fixture unreproducible (D.8). All three are now controls. The second strongest is the
boundary attack: `GESTEP` implemented as `>` instead of `>=` passes every casual check
(except at exactly `x = step`) — hence the corpus has `GESTEP(0, 0)` = 1 rows. The third
is reachability: a name can compile and dispatch and still be unreachable from a cell —
hence the three-probe reachability test and the `evaluateSheet` case. The fourth is the save
path: a name can evaluate correctly and still be written with the wrong prefix — hence
R122-1's prefix check, backed by the XlsxWriter table.

What this adversary does **not** touch: Excel's own last-ULP values (out of scope, stated),
and a shared bug between generator and gate (they are the same `render()` — R122-5 guards
reproducibility, not independence; the Kotlin test in CI is the independent check against
the fixture).
