# R123 — `CHISQ.TEST` / `F.TEST` / `Z.TEST` / `T.TEST` / `SKEW.P`, statistical test functions

`FormulaEval.kt` could evaluate `BESSELJ`/`BESSELI`/`BESSELK`/`BESSELY`/`ERF.PRECISE`/`ERFC.PRECISE`/`PHI`/`DELTA`/`GESTEP`
— and could not evaluate `CHISQ.TEST`, `F.TEST`, `Z.TEST`, `T.TEST` or `SKEW.P`, the names Excel's own function
reference documents for statistical hypothesis tests. A measured check across `FormulaEval.kt` (`grep` for each
quoted name, `*.kt` outside `build/`) returned **zero** dispatch occurrences for all five names, so no other site
covered them. Every one of them returned `#NAME?` from a formula.

R123 adds the five names: **+1 dispatch branch (five names) and 5 helpers (`chisqTest`, `fTest`, `zTest`, `tTest`,
`skewP`) in `FormulaEval.kt`** (`CHISQ.TEST(actual, expected)` — chi-square test of independence; `F.TEST(array1,
array2)` — two-sample F test for equal variances; `Z.TEST(array, x, [sigma])` — one-sample Z test; `T.TEST(array1,
array2, tails, type)` — Student's t test; `SKEW.P(number1, ...)` — population skewness; wrong arity is `#VALUE!`)
and **+5 lines in `SpillSheetEngine.kt`** (all five names in the OOXML export prefix list, because Excel stores
future-function names with the `_xlfn.` prefix). No build file, no Android source, no existing function is modified.
The `regGammaLowerP` kernel (for `CHISQ.TEST`), `incompleteBetaContinuedFraction` kernel (for `F.TEST`), `NORM.S.DIST`
(for `Z.TEST`) and `TDIST.2T` kernels (for `T.TEST`) are reused unchanged — this round builds on them, it does not
rewrite them.

## A. Formal model

**Admissible objects.** Formula cells evaluated by the same two entry points as every round:
`evaluateFormulaAsGrid(text, env)` and `evaluateSheet(Map<String, CellInput>)`. Arguments arrive as `CellValue`
(`Num`, `Text`, `Bool`, `Empty`, `Err`). `CHISQ.TEST` takes two same-shaped 2D arrays; `F.TEST` takes two 1D arrays;
`Z.TEST` takes one 1D array, a mean, and an optional sigma; `T.TEST` takes two 1D arrays, tails (1 or 2), and type
(1, 2 or 3); `SKEW.P` takes one or more numbers. Total on the declared domain, with `#VALUE!` refusals outside it.

**Information/access model.** The evaluator sees only the cell values in `env` and the parsed AST. It has no clock,
no locale, no host function table beyond `kotlin.math`.

**Resource counted.** Nothing is bounded by this round: these are total scalar functions with declared refusals.
The counted quantities are *correctness* quantities — the default sigma for `Z.TEST`, the tails/type parameters for
`T.TEST`, and the numeric difference from an independent implementation.

**Success and failure, quantifier order.** For the numeric cases: **for every** probe in the corpus, the value `E`
the engine returns satisfies `|E − R| ≤ 1e-12 · max(1, |R|)`, where `R` is the documented definition recomputed
independently in `tools/gen_r123_stat_test_corpus.py`. For the refusals: **for every** declared wrong-arity or
non-numeric input, the engine returns exactly `#VALUE!` and never a number. `DELTA`-style IEEE 754 equality is not
relevant here; `SKEW.P` returns `#NUM!` for n < 3 or zero population standard deviation.

**Parameters, boundary conditions, units, tolerances.** `CHISQ.TEST` requires all expected values > 0 (else `#NUM!`);
`F.TEST` requires both variances > 0 (else `#NUM!`); `Z.TEST` requires sigma > 0 if provided (else `#NUM!`);
`T.TEST` requires tails ∈ {1,2} and type ∈ {1,2,3} (else `#NUM!`). Tolerance `1e-12` relative with an absolute
floor of `1e-12` for the corpus test.

**Adjacent problems that must not be substituted.** `CHISQ.TEST` vs `CHISQ.DIST.RT` (test vs distribution), `F.TEST`
vs `F.DIST.RT` (test vs distribution), `Z.TEST` vs `NORM.S.DIST` (test vs distribution), `T.TEST` vs `TDIST.2T`
(test vs distribution), `SKEW.P` vs `SKEW` (population vs sample skewness), and every Class A question.

## B. Outcome space

* **H+** — all five names become reachable from both evaluator entry points, keep the declared arity and refusals,
  agree with an independent implementation on 101 probes (70 numeric, 31 refusals), 12 JUnit cases, 7 gate rules
  and a byte-identity check on the corpus. **This is what happened**, modulo the CI evidence limits in §H.
* **H−** — impossible to *pass* this contract by adding names alone: a name that dispatches to the wrong kernel
  (`F.TEST` implemented as one-tailed instead of two-tailed) fails the corpus; a corpus generated by the code
  under test fails the meta-control (R123-5).
* **H∂** — the boundary surface: expected value = 0 in `CHISQ.TEST` → `#NUM!`; zero variance in `F.TEST` → `#NUM!`;
  sigma ≤ 0 in `Z.TEST` → `#NUM!`; invalid tails/type in `T.TEST` → `#NUM!`; n < 3 in `SKEW.P` → `#NUM!`. The
  corpus encodes all of them.

## C. Frontier

The frontier here is the definition of each test: `CHISQ.TEST` is the chi-square test of independence using the
regularized incomplete gamma function; `F.TEST` is the two-sample F test using the regularized incomplete beta
function; `Z.TEST` is the one-sample Z test using the standard normal CDF; `T.TEST` is Student's t test using the
t-distribution tail; `SKEW.P` is population skewness. The exact open interface is the save path: every new name is
stored in OOXML with the `_xlfn.` prefix. The gate pins both sides of that interface: dispatch presence and
export-prefix presence (R123-1).

## D. Negative space (≥15 shapes that look like a solution and are not)

1. Dispatching `CHISQ.TEST`/`F.TEST`/`Z.TEST`/`T.TEST`/`SKEW.P` but implementing `CHISQ.TEST` as `CHISQ.DIST.RT`
   directly without computing the chi-square statistic from the data — wrong function entirely.
2. Implementing `F.TEST` as one-tailed instead of two-tailed — p-values off by factor of 2, caught by corpus rows.
3. Forgetting the default sigma for `Z.TEST` — `Z.TEST({1,2,3}, 2)` must compute sigma from the data.
4. Using sample standard deviation (n−1) instead of population standard deviation (n) for `Z.TEST` default sigma —
   different p-values, caught by the corpus.
5. Implementing `T.TEST` type=2 (equal variance) as type=3 (unequal variance/Welch) — different df, different p.
6. Implementing `SKEW.P` as sample skewness (n−1 denominator) instead of population skewness (n denominator) —
   different values, caught by the corpus.
7. Returning `0` or `1` as integers instead of doubles — the corpus expects `1.0`/`0.0`.
8. Loosening `TOL` above `1e-12` (fails R123-6).
9. Generating the corpus from the Kotlin kernels (a transcript, not an oracle — detected by R123-5 byte-identity
   and by the gate recomputing each row from `gen_r123_stat_test_corpus.py`).
10. Hand-editing the corpus after generation (fails R123-5).
11. Adding names to the dispatch but not the corpus (unmeasured behaviour — fails R123-2).
12. Adding names to the corpus but not the dispatch (the test reads names it never evaluates — the reachability
    test has five probes that would fail in CI).
13. Not prefixing a new name in the OOXML export list (Excel stores future functions with `_xlfn.` — fails R123-1).
14. Using `assertEquals` on doubles without tolerance (flaky at last-ULP — the test uses
    `abs(got − want) ≤ TOL · max(1, |want|)`).
15. Dropping the refusal rows from the corpus (fails R123-2's five-refusal minimum per name).
16. Implementing `CHISQ.TEST` without checking that all expected values are > 0 — division by zero or negative
    expected values must produce `#NUM!`.

The modal shortcut is D.9: a fixture generated by the code under test. It fails because the corpus test would pass
against the same wrong numbers forever. R123-5 detects it.

## E. Mechanism portfolio (five distinct, kept independent until judged)

1. **Chi-square test via `regGammaLowerP`** (chosen for `CHISQ.TEST`). Central construction: χ² = Σ((a−e)²/e),
   df = (rows−1)(cols−1), p = CHISQ.DIST.RT(χ², df) = 1 − P(df/2, χ²/2). Reuses the `regGammaLowerP` kernel
   already used by `CHISQ.DIST.RT`. Proved: every numeric corpus row agrees with the generator to 1e-12.
   Cheapest falsification: `CHISQ.TEST({2,1;1,2},{1.5,1.5;1.5,1.5})` must be 0.41421617824252543. Gap: local.
2. **Two-sample F test via `incompleteBetaContinuedFraction`** (chosen for `F.TEST`). Central construction:
   F = larger_variance/smaller_variance, p = 2·F.DIST.RT(F, n1−1, n2−1). Reuses `incompleteBetaContinuedFraction`
   already used by `F.DIST.RT`. Proved: `F.TEST({1,2,3},{1,2,3})` = 1.0. Gap: local.
3. **One-sample Z test via standard normal CDF** (chosen for `Z.TEST`). Central construction: z = (x̄−μ)/(σ/√n),
   p = 1 − NORM.S.DIST(z). Reuses `erfApprox`-based NORM.S.DIST. Proved: `Z.TEST({1,2,3,4,5},3)` = 0.5.
   Gap: local.
4. **Student's t test via incomplete beta** (chosen for `T.TEST`). Central construction: three types (paired,
   equal variance, Welch), p from t-distribution tail via incomplete beta. Reuses the same mathematical kernel
   as `TDIST.2T`. Proved: `T.TEST({1,2,3},{1,2,3},2,2)` = 1.0. Gap: local.
5. **Population skewness via n-th moment** (chosen for `SKEW.P`). Central construction: n/((n−1)(n−2)) · Σ((xi−x̄)/σ)³
   with population σ. Proved: `SKEW.P(1,2,3,4,5)` = 0.0 (symmetric). Gap: local.

## G. Second-order adversary

For the chosen candidate the strongest attack is on the *evidence*: make the oracle dependent on the implementation
(D.9), make the tolerance hide a tail-direction error (D.8), or make the fixture unreproducible (D.10). All three
are now controls. The second strongest is the tail attack: `F.TEST` implemented as one-tailed passes every casual
check (one-tailed and two-tailed agree at p = 1.0 for equal variances) — hence the corpus has rows with unequal
variances where one-tailed and two-tailed differ. The third is reachability: a name can compile and dispatch and
still be unreachable from a cell — hence the five-probe reachability test and the `evaluateSheet` case. The fourth
is the save path: a name can evaluate correctly and still be written with the wrong prefix — hence R123-1's prefix
check, backed by the XlsxWriter table.

What this adversary does **not** touch: Excel's own last-ULP values (out of scope, stated), and a shared bug between
generator and gate (they are the same `render()` — R123-5 guards reproducibility, not independence; the Kotlin test
in CI is the independent check against the fixture).
