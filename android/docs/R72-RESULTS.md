## A. Contract and quantifiers (see [R72 plan](R72-PLAN.md))
Objects: byte arrays for `DocxPackage.read` and `FormulaXlsx.read` (declared 16 MiB input, 1 MiB part, 16 MiB expanded, 256 entries); `Ooxml.extractDocxText`/`extractXlsxSheet`, the production import path used by `MainActivity` (64 MiB input, 32 MiB part, 64 MiB expanded, 5,000 entries, 2 MiB selected XML); and `PlainWriterDocx.write` over arbitrary Strings. Resource counted: **decoded bytes** per entry and in aggregate, entry count, and exact name equality — not compressed size, claimed header sizes, CPU, heap or wall-clock time. Success: every accepted archive keeps each decoded entry ≤ its limit and the sum ≤ the archive limit with ≤ the entry cap and no repeated names; every archive exceeding a bound or repeating a name is refused before a parsed result is published. For the writer: every String above 131,072 UTF-16 units is refused before XML validation or UTF-8 encoding, and every accepted String emits identical bytes to the unguarded build.

## B. Outcomes
H+ (achievable, demonstrated below): counting directories and all names removes the reproduced bypass without changing accepted output. H−: these limits cannot make hostile Office parsing safe or bound inflater CPU/heap; process isolation, schema validation and content security remain absent. H∂: exact limits must pass and limit+1 must fail; duplicate **directory** names count; an entry may carry data despite a trailing `/`.

## C. Reproduced defects on the pinned baseline
The unchanged `aacae23` readers counted only non-directory entries and advanced with `closeEntry()`, so data inside a slash-suffixed entry was discarded without passing any counter. Running them on 40 independently built archives produced exactly **10 contract violations**: `dir-over`, `aggregate-over`, `aggregate-suffix-over`, `duplicate-dir` and `descriptor-dir-over` for each of DOCX and XLSX.

## D. Repair
Both readers now: count every decoded byte for **every** entry through a buffer capped at the remaining per-entry/aggregate budget plus one byte; add each name (files and directories) to one duplicate set; append to a buffer only for non-directories; and check `n > 0` progress. A separate early guard in `PlainWriterDocx.write` rejects Strings longer than 131,072 UTF-16 units before `validateXml` and the strict UTF-8 encode. Limits, accepted formats and defaults are unchanged.
