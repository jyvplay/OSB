## Quantitative interface bound (not a benchmark)

One uncompressed3840×2160 RGBA frame is **33,177,600bytes**.60frames/s requires **1,990,656,000bytes/s** before protocol overhead. With256×256RGBA dirty tiles, each tile is262,144bytes; k changed tiles at60Hz require15,728,640×k bytes/s uncompressed. No worst-case compression guarantee exists for arbitrary pixel data. Therefore a full4K browser/Office frame cannot be honestly transferred as one≤1MiB Binder transaction; use bounded tiles/shared graphics surfaces with real ownership/lifecycle tests. The implemented320×320 raw preview is≤409,600bytes plus metadata and is intentionally a MUCH narrower interface. These arithmetic bounds do not establish frame rate or physical performance.

## Hardware-origin impossibility boundary / common actionable mitigations

Model two machines that deliver exactly the same visible input events, device descriptors and app/OS API observations. In the second, a passive inline logger also records keyboard signals. For every observation-only app algorithm, both transcripts are identical; no such app can always distinguish logger presence. A hostile host/firmware can similarly simulate the expected APIs while observing guest data. This is a causal indistinguishability argument under its explicit observation model, not a theorem-prover run or a claim every hardware attack is undetectable.

Useful actions remain: no-IME pointer-only entry against keyboard-only logging under trusted platform, ordinary secure-window/overlay restrictions, volatile discard on real noninteractive state, authenticated privileged USB admission/IOMMU policy managed by the HOST with recovery input, trusted firmware/update/custody and hardware authenticators for suitable authentication protocols. None attests all hardware, protects a compromised host, anonymizes prior chat/GitHub/ISP logs or proves RAM/flash erasure. Generic browser+Tor proxy also lacks Tor Browser's anti-fingerprinting/origin protections. See fresh primary ledger r24-primary.md.
